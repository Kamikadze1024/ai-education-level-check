1) # аутентификация пользователей
POST /core/auth

тело запроса - json вида:
{"login":"<login_value>", "password": "<password_value>"}

ответ корректный:
//не прошел аутентификацию
{"result": "fail"}

//прошел аутентификацию
{
    "result": "ok",
    "role": "admin/student"
}

//любое отличное от этих сообщение - ошибка

Этот пункт обрабатывает нашу форму с аутентификацией. Он выдает сообщение об ошибке
аутентификации, либо информацию о том, какая роль залогинилась (администратор или обучающийся),
либо сообщение о непридвиденной ошибке (Oops, "что-то пошло не так..." или что-то в этом роде).

Если аутентификация прошла корректно - нужно перейти в страницу администратора или студента в
зависимости от поля "role".

/*
    Для администратора. Эти методы фронт "дергает", исключительно
    со страницы администратора.

    Страниц администратора у нас:
    1 - диалог загрузки базы знаний
    2 - диалог создания списка заданий из загруженной базы знаний
    3 - отображения сгенерированного списка вопросов
*/
2) # загрузка файла из фронта в бэк (страница диалога загрузки базы знаний - 1)
POST /gen/upload_know_base

тело запроса - файл (pdf/txt и так далее)

//успех - http код 200

//провал - любое другое сообщение (и любым http кодом кроме 200)

Предложение загрузить базу знаний это первое, что должен увидеть администратор.
Без успешной загрузки не должно быть предложений сгенерить список вопросов.
При ошибке - сообщить пользователю о ней и предложить попробовать снова.
При успехе - перейти на страницу администратора (2 - диалога создания списка заданий)

3) # генерация списка вопросов (страница диалога создания списка заданий из загруженной базы знаний - 2)
POST /gen/questions

тело запроса - json вида:
{
    "num_questions": x, //к-во запросов
    "num_answ_per_one_quest": y, //к-во вариантов ответа на один вопрос
    "num_correct_answ_per_one_quest": z //к-во правильных ответов на
}

ответ - json вида:
//успех
{
    "msg_type": "questions_list", //это просто название поля (постоянно)
    "questions": [
        {
            "question_num": 1, //номер вопроса 1, 2, ....
            "question_txt": "<формулировка вопроса>", //текстовка вопроса
            "correct_answs": [//массив правильных ответов
                {
                    "answ_txt": "<текст правильного ответа>"
                }
            ],
            "not_correct_answs": [//массив неправильных ответов
                {
                    "answ_txt": "<текст неправильного ответа>"
                }
            ]
        }
    ]
}

//провал - любое другое сообщение (и любым http кодом кроме 200)

На этой странице - настройка количества вопросов, количества ответов к каждому из вопросов (всего),
и количества правильных ответов к каждому из вопросов.

В случае провала генерации - сообщение об ошибке и предложение повторить.
В случае успеха - отображение страницы администратора (3) - отображения
сгенерированного списка вопросов.


4) # сохранение списка вопросов в базу (страница администратора 3 - отображения сгенерированного списка вопросов)
POST /gen/save_questions

тело запроса - ответный json из пункта 2 (метод  /gen/questions - тот что со сгенерированными вопросами)

ответ - json вида:
//успех
{
    "quest_list_id": <идентификатор сохраненного в базу списка вопросов>
}

//провал - любое другое сообщение (и любым http кодом кроме 200)

Страница пока просто отображает сгенерированный список вопросов с ответами
и подсвечивает правильные из них и имеет кнопку "Подтвердить". При ее
нажатии выполняется метод из этого пункта.
В случае успеха - пользователю отображается сообщение об успешном добавлении
этого списка заданий под идентификатором из ответного сообщения. После реакции
пользователя - приложение выкидывает пользователя на страницу логина - пароля.
В случае неуспеха - приложение сообщает об ошибке и предлагает повторить
через эту уже открытую страницу.


/*
    Для обучающегося

    Страниц для обучающегося у нас:
    1 - страница отображения списка доступных студенту экзаменов(списков вопросов)
    2 - страница отображения конкретного экзамена для студента
*/
5) # запрос списка доступных для студента заданий (выполняется перед отображением первой страницы студента (после логина))
GET /exam/get_available_exams

ответ - json вида:
//успех
{
    "available_exams": [//тут просто пока идентификатор экзамена (списка вопросов)
        //в этом массиве может быть много элементов, т.к. в базе может быть
        //сохранено списков вопросов достаточно много
        {
            "available_exam_id": <идентификатор доступного списка вопросов>
        }
    ]
}

//провал - любое другое сообщение (и любым http кодом кроме 200)

В случае неуспеха запроса - выдается сообщение об отсутствии доступных
экзаменов (списков вопросов). После реакции пользователя на это - выкидывать
его на страницу ввода логина - пароля.

В случае успеха запроса - отобразить на форме табличку с радиобаттонами
идентификаторов доступных экзаменов (она же 1 - страница отображения списка доступных
студенту экзаменов(списков вопросов)), чтобы пользователь смог выбрать только один.
По-умолчанию, выбран только первый из них.

На этой странице должна быть еще кнопка "приступить к экзамену". При ее нажатии,
происходит переход на страницу 2 - страницу отображения конкретного экзамена для
студента.

6) # проведение оценочного тестирования (выполняется со 2 страницы студента)
POST /exam/execute

тело запроса - json вида:
{
    "msg_type": "exam_procedure", //это просто название поля (постоянно)
    "answers": [
        {
            "question_num": 1, //номер вопроса 1,2, ....
            "user_answs": [ //массив ответов пользователя
                {
                    "answ_txt": "<текст ответа пользователя>"
                }
            ]
        }
    ]
}

ответ - json вида:
//успех
{
    "correct_answs": <количество правильных ответов>,
    "incorrect_answs": <количество неправильных ответов>
}

//провал - любое другое сообщение (и любым http кодом кроме 200)

Это 2я страница студента (отображения конкретного экзамена у студента).
На ней и производится пока весь экзамен.
Имеет вид таблички с вопросами, к каждому из который даны чекбоксы,
которые позволяют студенту выбрать один или несколько правильных.
И кнопка - "сдать экзамен". При ее нажатии, выполняется этот заопрос.
В случае провала - сообщение об ошибке и предложение попробовать снова.
В случае успеха - отображается окошко с результатом. Как только пользователь Подтвердит
- выброс на окно логина и пароля.
